## 源码中的测试数据

测试含明确公开的 TEST ONLY CA、客户端 PKCS#12 和固定测试密码，以及重复字节/运行时随机生成的 WireGuard 测试密钥。
这些不是部署凭据，但公开测试私钥也不能用于真实服务或设备；绝对不要安装测试 CA 到真实设备。
示例域名使用保留的 example/test 域或明示离线模拟的 DDNS 测试域，不应当作实际部署地址。

## 应用运行

- 没有项目云服务、广告或分析 SDK。
- 密钥、Peer 和 DDNS 设置在应用私有加密存储中；不允许应用备份。
- DDNS 提供商会接收域名、公网 IPv6 和其所需授权信息；DNS-only DDNS 不转发 VPN 流量。
- 四站网络检查会向所列官网发送固定 HTTPS 请求，网站能看到出口 IP 等普通连接元数据，但请求不附带应用密钥、DDNS Token 或设备标识。
- Root 检查需要用户操作/授权；不自动变更 SELinux、系统安全或防火墙设置。
- 本地导出配置、剪贴板和相册可能被其他应用读取/同步，管理员必须自行保护。

## 检查与限制

`tools/verify-public.py` 逐条检查源 ZIP、嵌套 Wrapper JAR 和 PNG 结构，不打印匹配到的凭据值。
它禁止源码包包含 AAR/APK、缓存、签名、日志等；构建后不能把整个工作目录重新压缩发布，应重新按发布白名单整理。
普通扫描无法数学证明任意未知内容没有秘密；实际发布还需人工核对、证书解析、来源审查和最终档案检查。
发布核验记录见 [VERIFICATION.md](VERIFICATION.md)。后续添加文件必须重新审查。
